# 基于MindSpore的园区安全智能调控平台 — 分类需求分析文档

> 依据：《中期考核.pdf》系统需求（要求一~七）与《项目分工/分工总结文档》的职责划分
>
> 编号规则：FR = 功能需求，NFR = 非功能需求

## 一、需求概述

园区、场馆人流密集时段安全风险高，易出现拥堵、交通安全等隐患；外来车辆未经授权进入可能带来安全隐患，尤其在人流高峰时段需要严格管控。平台需实现：人流实时监测、门闸动态调节、外来车辆准入智能判断、拥堵风险预警与应急响应等功能，兼顾宏观交通拓扑网络分析与微观车联网交通汇合（MAS+CAV）两个层面，支撑 3000 人以上正常运行。

**技术栈：** MindSpore + 昇腾硬件 + ModelArts / Python（后端）+ Vue/React（前端）+ MySQL/PostgreSQL（数据库）

## 附录 A：2.3 节（MAS+CAV）实施方案说明

### A.1 结论：直接电脑仿真即可

题目原文："在车辆行进管理上可考虑采用 MAS+CAV……（需要探究应用 CAV 提速了多少）"。本模块本质是一次**对比实验**（有 CAV vs 无 CAV），无需真实路测，纯 Python 仿真即可交付。

### A.2 实施步骤

| 步骤 | 做法 |
|---|---|
| 1. 环境输入 | 从 F 的仿真引擎/随机生成器获取道路拓扑 + 人流密度数据（或先用 A 的 Dijkstra 结果作路径） |
| 2. 对照组（无 CAV） | 经典车辆跟驰模型，如 IDM（智能驾驶员模型），每车独立决策 |
| 3. 实验组（有 CAV） | 加入车联网协同：编队（platoon）/ 恒定车头时距 CTH / 汇合点协商让行 |
| 4. 仿真循环 | tick 步进（每步更新所有车辆 Agent 位置、速度、状态），记录全行程数据 |
| 5. 量化指标 | 平均通行时间、汇合点通过率、道路吞吐量、延误减少百分比 |
| 6. 输出 | matplotlib 曲线图（有无 CAV 对比）+ 量化分析段落（写入分工文档交付物） |

### A.3 框架选型说明

- **Mesa**：Python 多智能体仿真框架（Agent-Based Modeling），通过定义 `Agent.step()` 推进仿真。作用在于"仿真怎么跑"。
- **sklearn 风格接口**：本项目"算法接口统一遵循 sklearn 风格"是标准五的硬性要求，指算法对外暴露 `fit / predict / transform` 接口。作用在于"接口怎么设计"。

**二者不是二选一，而是同时使用**：

| 用途 | 用什么 |
|---|---|
| 仿真本体（跑 Agent、tick 循环） | Mesa **或** 自写循环（均可，自写更省依赖、更贴"代码不冗余"标准） |
| 算法对外接口（如 `CavSimulator.fit(data).predict()`） | 按 sklearn 风格自行封装 |

推荐：**自写 tick 循环 + sklearn 风格接口封装**（可读、可控、满足检查标准）。

### A.4 关于 MATLAB

技术可行，但不推荐：

| 维度 | MATLAB | Python |
|---|---|---|
| 与团队技术栈 | 无法对接 MindSpore/ModelArts/昇腾、无法 sklearn 风格统一接口 | 完全一致 |
| 与 F/D/E 联调 | 只能手动 CSV 导出导入，联调困难 | 函数级直接调用 |
| 数据可视化 | 能出图，但导出给 E 麻烦 | matplotlib 出图 + CSV 直通 E |
| 版权 | 需正版 License | 免费开源 |

结论：仿真数据消费方（F 仿真引擎、D AI 预测、E 可视化）均在 Python 侧，建议 Python 实现。若个别成员仅会 MATLAB，可先用 MATLAB 出对比数据，再由 Python 封装接口供 D/E 消费，但会增加工作量。

### A.5 数据对接关系

- C ← F：微观仿真数据输入
- C ← A：宏观路径（Dijkstra）结果
- C → D：通行效率结果，供预测驱动调度
- C → E：可选，导出 CSV 供可视化大屏展示 CAV 对比图

### A.6 可选加分项

如需答辩更直观，可为汇合过程制作 pygame/HTML 动画 demo，但非必需交付项。

## 附录 B：核心概念解释

> 说明：本附录澄清项目中的关键概念，后续如有新概念疑问可继续追加（B.4、B.5…）。

### B.1 门闸是什么（与红绿灯的区别）

| 类型 | 对应实物 | 控制对象 | 管什么 |
|---|---|---|---|
| 道闸/栏杆 | 停车场抬杆、园区大门栏杆 | 车辆 | 准入权限（能不能进） |
| 闸机/门禁 | 地铁闸机、场馆入口闸机 | 行人 | 准入权限（放多少人进） |
| 红绿灯 | 道路交叉口信号灯 | 人流/车流 | 通行顺序（谁先走） |

要点：
- 公共道路**没有准入概念**（谁都能进），所以只需红绿灯管通行顺序
- 园区是**有边界、有出入口**的封闭区域，多了"准入"问题，因此需要门闸
- 本题"门闸动态调节"管的是**园区出入口的准入**与热点节点通流（调节通过速率：开几道闸、何时放行、往哪放），**红绿灯不在本题范围内**
- 门闸 ≠ 只调"出口"：入口（车辆进不进来）、内部关键节点（疏散）都有闸

### B.2 疏导栏杆的含义

移动围栏（演唱会、地铁早高峰、景区常见），作用：
1. 防人流对冲——出入口"进/出"两侧隔开
2. 蛇形限流减速——强制放慢进入速度
3. 引导疏散——拥堵时引导人群走备用通道

题目原文"给出需要安排人员疏通的节点、疏散路径等"即此。本项目仿真中**以策略建议输出实现**（F 门闸策略 + D 安全预警/应急响应产出处置建议），无需绘制实物。

### B.3 园区内车辆交通处理链路

```
外来车到园区门口
  ├─ ① 车辆准入判断（C 的 VehicleAccessPolicy）
  │     人流密度低 → 放行；人流密度高 → 拒入 / 限制时段进入
  │
  ├─ ② 行进路线规划（A 的 Dijkstra + 人流密度加权边权值）
  │     避开人流密集区，取"人少路近"折中路径
  │
  ├─ ③ 行进过程 MAS+CAV 协同（C 的 CavSimulator）
  │     多车编队、汇合点协同，减少园区内拥堵
  │
  ├─ ④ 行驶路径等敏感数据 DP 差分隐私保护（C 的 DpNoiseScaler）
  │
  └─ ⑤ 全程联动门闸（抬杆/落杆）+ 路况上报
```

内部车辆（已注册本园区车）：免准入，但同样纳入路径规划、密度监测与 CAV 协同。

一句话总结：**门闸管"边界准不让你进"，红绿灯管"路口谁先走"，园区内车辆怎么走由"准入 + 路径规划 + CAV 协同"负责。**
