# 变量及接口命名规范（v1.0）

> 项目：基于 MindSpore 的园区安全智能调控平台
>
> 版本：v1.0 ｜ 日期：2026-08-01 ｜ 适用范围：全部 Python 代码
>
> 核心约定：算法模块强制遵循 sklearn 风格接口（fit / predict / transform），MindSpore 仅作内部实现；运行时环境为 Linux（WSL + 服务器，详见附录 B）

## 一、命名总则（PEP 8）

| 对象 | 规范 | 示例 |
|---|---|---|
| 模块/包 | 小写+下划线 | `macro_topo`, `cav_sim` |
| 类 | 大驼峰 PascalCase | `DensityPredictor`, `TrafficNetworkAnalyzer` |
| 函数/方法 | 小写+下划线 | `predict_proba`, `get_params` |
| 变量/属性 | 小写+下划线 | `max_depth`, `n_samples` |
| 常量 | 全大写+下划线 | `MAX_SPEED` |
| 私有 | 前置单下划线 | `_validate_input` |

## 二、sklearn 风格核心接口（所有算法模块的对外接口，强制）

### 2.1 核心方法签名

| 方法 | 签名 | 约定 |
|---|---|---|
| `fit` | `fit(X, y=None)` | 训练/学习，**必须返回 self** |
| `predict` | `predict(X)` | 预测，返回数组（不返回 self） |
| `transform` | `transform(X)` | 数据变换，返回数组 |
| `fit_transform` | `fit_transform(X, y=None)` | = fit 后 transform |
| `fit_predict` | `fit_predict(X, y=None)` | = fit 后 predict（聚类/异常检测用） |
| `predict_proba` | `predict_proba(X)` | 概率输出（如有） |
| `score` | `score(X, y=None)` | 模型评估得分 |
| `get_params` | `get_params(deep=True)` | 获取超参数 |
| `set_params` | `set_params(**params)` | 设置超参数，**返回 self** |
| `partial_fit` | `partial_fit(X, y=None, classes=None)` | 增量训练（可选） |

> **各方法的调用方式与完整代码示例见同目录《核心接口使用示例.md》**

### 2.2 参数与数据命名

- `X`（大写）：样本×特征二维数组 `(n_samples, n_features)`；`y`（小写）：目标一维数组
- 通用参数名统一：`n_estimators`、`max_depth`、`random_state`、`n_jobs`、`sample_weight`
- 可选条件参数默认 `None`

### 2.3 属性命名（尾下划线规则——sklearn 精髓）

- **构造参数**：`__init__` 收到的参数原样存为同名属性，**不加下划线**（`self.max_depth = max_depth`）
- **从数据学到的**：加**尾下划线 `_`**（`coef_`、`classes_`、`n_features_in_`、`mean_`、`n_iter_`）
- 例：`model.n_features_in_`（fit 后才有），而 `model.max_depth`（用户设定）

### 2.4 其他硬性约定

1. `__init__` **只做参数赋值，不校验、不计算**；校验放在 `fit`（如 `check_array(X)`、`check_X_y(X, y)`）
2. `fit` 开头记录特征数 `n_features_in_`，`predict/transform` 校验输入特征数一致，否则抛 `ValueError`
3. 数值计算返回 `numpy.ndarray`
4. 类必须带 docstring，含 `Parameters` / `Attributes` / `Examples` 分区
5. 构造参数名与类名可对应检索（`DensityPredictor(n_layers=..., lr=...)`）

## 附录 B：Linux 服务器运行约定

### B.1 路径约定

**pathlib 是什么（通俗解释）**：`pathlib` 是 Python 自带（标准库）的路径处理模块，用来代替手写字符串拼路径。它最核心的作用是**自动适配 Windows 和 Linux 两种路径写法**——同样的代码，在 Windows 上自动用 `\`，在 Linux/WSL 上自动用 `/`，不用自己判断。

```python
from pathlib import Path

# 坏例子：写死绝对路径（换台电脑就崩）
model_dir = "D:/Documents/project/models"   # Windows 上能跑，WSL 里不存在
model_dir = "/home/ubuntu/project/models"   # 你的 WSL 能跑，队友电脑崩

# 好例子：以项目根目录为基准拼路径（任何机器都能跑）
base_dir = Path(__file__).resolve().parent.parent   # 自动定位项目根
model_dir = base_dir / "models"                     # 支持 "/" 拼接，跨平台
data_dir = base_dir / "data"
```

**配置注入**：可变的路径（模型目录、数据目录、日志目录）和运行参数不写死在代码里，而是集中写进配置文件，代码只负责"读配置"。这样换机器、换环境只需改配置文件，不用改代码。

**config.yaml 范例**：

```yaml
# config.yaml（放在项目根目录）
paths:
  data_dir: ./data        # 仿真数据、数据集
  model_dir: ./models     # .ckpt 权重 + model_config.yaml
  log_dir: ./logs         # 日志文件

database:
  host: 127.0.0.1
  port: 3306
  user: admin
  password: ${DB_PASSWORD}   # 敏感信息不写死，用环境变量引用

train:
  device_target: GPU      # 本地 WSL 训练用 GPU；ModelArts 部署时改为 Ascend
  seed: 42
```

```python
# 代码读取方式（统一封装成 config.py，其他人直接 from config import config）
import yaml
from pathlib import Path

config = yaml.safe_load(Path("config.yaml").read_text(encoding="utf-8"))
model_dir = Path(config["paths"]["model_dir"])
```

**敏感信息（数据库密码等）**用 `.env` 文件 + 环境变量管理，`.env` 加入 `.gitignore` 不进仓库：

```
# .env（仅本机存在，不入 Git）
DB_PASSWORD=your_password_here
```

### B.2 环境

WSL(Ubuntu) + conda 管理 Python 3.10+ 环境，`requirements.txt` 固定版本；MindSpore 用 GPU(CUDA) 版本地训练，昇腾环境仅在 ModelArts 部署环节使用。

### B.3 模型产物

训练脚本（`train.py`）与推理接口（sklearn 风格类）分离；保存 `.ckpt` + `model_config.yaml` 到 `models/`（路径由 config 指定），加载路径由配置注入。

### B.4 训练约定

训练前统一固定随机种子（`mindspore.set_seed` + `np.random.seed`）保证初始化一致，但后端不保证完全可复现；**可复现性以保存参数为准**——训练结束必须保存 `.ckpt` 权重 + `model_config.yaml`（超参数与种子）+ 训练日志，推理一律加载已保存的 `.ckpt`，不重复训练。

### B.5 日志

格式见附录 D（统一 `[时间戳][级别][模块.方法] 消息`，输出控制台 + `logs/` 按日期的文件，路径由 config 指定）。

### B.6 文件格式

换行 LF、编码 UTF-8、无 BOM；文件权限遵循 Linux 惯例。

## 附录 C：MindSpore 内部实现约定（仅 D 模块神经网络的内部层）

**原则：对外接口 sklearn 风格（fit/predict），MindSpore 只出现在类的内部实现。**

| 对象 | 规范 | 示例 |
|---|---|---|
| `nn.Cell` 子类 | 类名以 `Net` 结尾 | `DensityNet`, `AnomalyNet` |
| 前向函数 | `construct()`（MindSpore 约定，**不得对外暴露**） | `self._net.construct(x)` 由框架调用 |
| 训练入口 | 内部用 `Model.train()` 封装 | 封装在 `DensityPredictor.fit()` 内 |
| 网络内部参数 | 以 `self.` 存于 `nn.Cell` 内（如 `self.fc1`） | 不对外暴露 |
| 权重保存 | MindSpore CheckPoint `.ckpt` | `models/density_predictor.ckpt` |
| 训练脚本 | `train.py`（独立脚本，不 import 推理逻辑） | 服务器上执行 |

**示例（对外 sklearn / 对内 MindSpore 双轨）：**

```python
class DensityPredictor:
    def __init__(self, n_layers=3, lr=1e-3):
        self.n_layers = n_layers      # 构造参数，不加下划线
        self.lr = lr

    def fit(self, X, y=None):
        self._net = DensityNet(n_layers=self.n_layers)
        self._train(X, y)             # 内部调用 Model.train
        self.n_features_in_ = X.shape[1]   # 学习属性，加下划线
        return self

    def predict(self, X):
        return self._net(X)           # 内部使用 MindSpore
```

**选择理由**（sklearn 对外 vs MindSpore 原生接口）：
1. 检查标准五原文要求"算法接口统一（可模仿 sklearn 的标准）"，答辩评分项
2. Dijkstra / PageRank / AttractRank / IDM 跟驰 / DP 加噪等非神经网络算法只能用 sklearn 风格统一
3. MindSpore 官方 `mindspore.sklearn`（mstoolkit）即此模式，两者天然兼容
4. `mindspore.Model` 的 `train/eval/predict` 只适用于神经网络且语义与 sklearn 不一致，不作统一标准

## 附录 D：日志统一格式

- 统一使用 Python 标准库 `logging`，logger 名为模块名（`logging.getLogger(__name__)`）
- 输出格式：`[时间戳][级别][模块.方法] 消息`
- 示例：`2026-08-03 14:30:00 [INFO] [density_predictor.fit] epoch=10 loss=0.0123`
- 训练日志固定字段：`epoch` / `loss` / 评估指标；每 N 个 epoch 输出一条
- 同时输出到控制台与 `logs/` 目录下按日期的文件（路径由配置指定）
