## 二、Step 0：`movement_cav.py` 修改说明

**问题**：引擎 `step()` 每 tick 只调用一次 `movement.update_speed(pool)`（engine.py:512），且没有其他写 `speed` 的地方（出生时 speed=0）。原 `CavIdmMovement` 只更新车辆（`kind==1`），**启用后行人 speed 恒为 0 → 全园行人卡死**。

**修改**（2 处）：

1. 新增导入：
```python
from topology import Topology
```

2. `update_speed()` 末尾新增行人兜底（第 6 步）：
```python
# 6. 行人兜底：引擎每 tick 只调用本插件更新速度（engine.step 无其他写速度处），
#    若不在此为行人写回巡航速度，行人 speed 将恒为 0 而全局卡死。
ped_mask = data["active"] & (data["kind"] == 0) & (data["state"] == 1)
if np.any(ped_mask):
    data["speed"][ped_mask] = Topology.base_speed(0)
```

**语义**：与 `ConstantSpeedMovement` 行为一致（行人 1.3 m/s 固定巡航）；车辆逻辑零改动。

**验证结果**（真实拓扑 61 节点）：
- 插件单测：行人 speed=1.30 ✓；同边车辆均获得正速度 ✓
- 端到端（300 人/80 车/1h 投放/3600 tick）：TRAVEL 行人平均 speed=1.300 m/s，无卡死；到达回收行为与 ConstantSpeedMovement 基线一致 ✓
- 性能：tick_mean_ms=0.51（基线 constant=0.50），无退化 ✓

## 三、Step 2：`simulation/cav_pack.py`（新增）

**职责**：union_pack 打包采集，两个对外函数（无状态、纯函数式接口）：

### `collect_cav_stats(eng) -> dict`（实时段，每 interval=10 tick 随 union_pack 打包）
- **只统计从大门(门闸)入园的车辆**：掩码 `active & kind==1 & src_node ∈ topology.gate_nodes`
- 返回：`{avg_speed_kmh, low_speed_ratio, n_vehicles, n_low_speed}`
  - `avg_speed_kmh`：移动中（state==1）车辆瞬时速度均值 ×3.6
  - `low_speed_ratio`：全在场门入车辆中 speed<5km/h（1.39 m/s）占比
- 空车流返回全 0，不抛异常

### `pack_micro_results(path=None) -> dict`（离线段）
- 读取 `compare_cav.py` 产出的 `项目目录/data/micro_validation_results.json`
- 文件缺失/JSON 损坏返回 `{}`，不中断打包链路

**验证**：`python simulation/cav_pack.py` 自测通过（缺失文件返回 {}）；端到端采样序列正常（门入车辆数 3→36，移动中车辆 ~18 km/h）。

## 四、Step 4：`compare_cav.py`（新增，离线对比）

**职责**：真实拓扑 + 同一车流（同一个 `FlowDataGenerator`，seed 固定）跑两轮：
- `CavIdmMovement(mode="idm")` 对照组 / `CavIdmMovement(mode="cav")` 实验组
- 基于引擎 trip 钩子（`eng.trip_logs_`，**依赖 F 合入 engine.py 改动**）汇总输出

**输出**：`项目目录/data/micro_validation_results.json`，结构：
```
{ meta, per_node, od_stats }
per_node[节点] = { avg_speed_idm, avg_speed_cav, efficiency_gain_pct,
                   avg_delay_time, throughput, n_trips,
                   avg_travel_time_idm, avg_travel_time_cav }   # 按 dst_node 归集
od_stats["src|dst"] = { trips, avg_travel_time_idm|cav, avg_speed_idm|cav }  # O-D 对维度
```
- 统计范围：仅大门入园车辆（与 cav_stats 同口径）
- `meta` 中写明口径：delay=信号排队+低速行驶（不含计划性出发等待）；per_node 按 dst 归集（引擎无节点穿越记录，近似）

**用法**：
```bash
cd 项目目录
python compare_cav.py --selftest              # 纯逻辑自测（已通过，不依赖引擎）
python compare_cav.py                          # 1000人/80车/1h窗口/3600tick
python compare_cav.py --n-people 2000 --n-vehicles 300 --n-ticks 7200 --n-hours 2
```
- `--n-hours`：投放窗口小时数（越小车流越集中，越能体现跟驰/编队差异）

**前置条件**：F 合入 trip 钩子（engine.py）后即可运行；未合入时脚本打印阻塞提示并退出（退出码 1）。

**验证**：`--selftest` 通过（大门入园过滤 / per_node 归集 / od_stats / 指标公式 全部断言通过）。

## 五、micro_validation_results 字段详细说明（数据链路与字段定义）

### 5.1 数据链路（每个字段的来源）

```
车辆计划 flow_data_generator（vehicles.csv: id / birth_tick / src_node / dst_node / is_internal）
  → 引擎 _spawn_batch 落 pool.data（src_node / dst_node 字段保留，出生 speed=0）
  → 路径规划：topology.path(src, dst, kind=1)（Dijkstra，经 ShortestPathFinder；
     出生时算好并缓存，缓存键 (src_idx, dst_idx, kind)，控制状态变化才失效
     = "路径规划之后就固定"）
  → 行驶：movement.update_speed 每 tick 更新车辆 speed（IDM / CAV 动态）
  → trip 钩子（engine.py，待 F 合入）：
      出生  : _spawn_batch 记 _birth[slot] = 过闸入园时刻
      途中  : 每 tick 向量化累计 _spd_sum += v·dt（仅 state==TRAVEL 时）、
              _delay_sum += dt（信号排队 state==WAIT_SIGNAL，或低速 v<1.39 m/s）
      到达  : _on_reach 到达终点分支落一条 trip_logs_ 记录
              {src_node, dst_node, birth_tick, finish_tick, travel_time,
               avg_speed_kmh, delay_time}
  → compare_cav.py aggregate_trips() 汇总 → micro_validation_results.json
      { meta, per_node, od_stats }
```

### 5.2 `per_node[节点ID]` 字段定义表（按 dst_node 归集）

| 字段 | 类型 | 定义（公式） | 单位 | 来源 |
|---|---|---|---|---|
| `avg_speed_idm` | float | 该域内对照组（idm）各 trip 的 `avg_speed_kmh` 算术均值 | km/h | trip 钩子 `_spd_sum` |
| `avg_speed_cav` | float | 同上，实验组（cav） | km/h | 同上 |
| `efficiency_gain_pct` | float | `(avg_speed_cav − avg_speed_idm) / avg_speed_idm`；当 `avg_speed_idm ≤ 0` 时为 0 | 小数（0.784 = +78.4%） | 由前两字段计算 |
| `avg_delay_time` | float | 该域内（idm+cav 合并）所有 trip 的 `delay_time` 均值 | 秒 | trip 钩子 `_delay_sum` |
| `throughput` | int | 该域到达车辆数 = `max(idm 到达数, cav 到达数)` | 辆 | trip_logs_ 条数 |
| `n_trips` | int | 该域样本车辆数（= throughput） | 辆 | 同上 |
| `avg_travel_time_idm` | float | 该域内 trip 的 `travel_time` 均值 | 秒 | `finish_tick − birth_tick` |
| `avg_travel_time_cav` | float | 同上，实验组 | 秒 | 同上 |

**关键口径说明**：
1. 单辆车的 `avg_speed_kmh = _spd_sum / (finish_tick − birth_tick) × 3.6`，即"门到门平均速度"（真实行驶里程 ÷ 总耗时，总耗时含排队/等待）；
2. 节点归集口径：**按 dst_node（目的地）归集**——引擎当前不记录车辆经过的中间节点序列，属近似口径（`meta.per_node_aggregation` 中注明）；
3. 对照组/实验组**共享同一车流**（同一个 FlowDataGenerator + 固定 seed），唯一差异是 movement 插件（idm / cav），保证对比公平；
4. 统计范围：仅 `src_node ∈ gate_nodes`（大门入园车），与实时段 `cav_stats` 同口径。

### 5.3 `od_stats["src|dst"]` 字段定义表（O-D 对维度）

| 字段 | 定义 | 单位 |
|---|---|---|
| `trips` | 该 O-D 对的门入样本车辆数 | 辆 |
| `avg_travel_time_idm` / `_cav` | 该 O-D 对微观真实通行时间均值 | 秒 |
| `avg_speed_idm` / `_cav` | 该 O-D 对门到门平均速度均值 | km/h |

### 5.4 O-D 维度与 union_pack.vehicle_paths 的宏微对照（协作 4/8 验证点）

- `union_pack.vehicle_paths` 是**静态 Dijkstra 结果**：`travelTime` = 各边边权之和（`engine.vehicle_paths_json()` → `topology.network.get_edge_weight()`，自由流/固定速度，路径规划后不变）；
- `od_stats` 是**微观真实值**：含 IDM 停车排队 / CAV 编队通过 / 信号等待等全部动态过程；
- 同一 O-D 对下：`静态值 − 微观值 = 宏观规划未预见的微观时延`；CAV 模式下该差值显著缩小——这正是"宏微闭环对齐"的量化验证点（C 给 A，协作 4/8）；
- 起点终点：**汇总口径**（per_node 纯聚合）确实不显式携带 O-D，但 `od_stats` 段以 `src|dst` 为 key 完整保留 O-D 维度；底层 trip 日志每条都含 `src_node / dst_node`，可随时回溯。

### 5.5 为什么必须用 trip 钩子（而非旁路采样）

- 引擎 `entity_dtype` **没有出生时刻字段**，旁路快照无法计算"通行时间"；
- 旁路瞬时速度均值会受**在场车龄结构污染**（老车多 → 均值系统性偏低），trip 钩子是逐车全程统计，口径干净，IDM vs CAV 对比才可信。
