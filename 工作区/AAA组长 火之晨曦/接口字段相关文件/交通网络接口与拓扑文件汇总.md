## 一、数据结构定义

### 1.1 内部数据结构（Python / YAML 层，snake_case）

```python
@dataclass
class TopoNode:
    id: str              # node_id，全园区唯一（A 为唯一来源）
    name: str            # 节点名称（如"食堂"）
    x: float             # 地图坐标
    y: float
    type: str            # entrance / cross_road / divergence / hotspot / stop
    gate_id: str = ""    # 门闸编号（仅 entrance 节点，引用 B 门闸表）

@dataclass
class TopoEdge:
    src: str             # 起点 node_id
    dst: str             # 终点 node_id
    weight: float        # 静态通行时间（分钟）
    capacity: int        # 通行能力（人/分钟）

class TrafficNetwork:
    """加载 topology.yaml → 邻接表"""
    def __init__(self, path: str = "topology.yaml"): ...
    def load(self) -> "TrafficNetwork": ...
```

### 1.2 REST 层字段命名约定

> 引擎内部 `snake_case`（`node_id`）→ REST 冻结 `camelCase`（`nodeId`），转换层由 **B（张紫桐）后端** 负责。

| 内部字段 | REST 字段 |
|---|---|
| `id` | `nodeId` |
| `name` | `nodeName` |
| `gate_id` | `gateId` |

## 三、REST 接口 JSON 样例（camelCase，B 冻结用）

### 3.1 ① 节点监控接口

`GET /api/v1/network/nodes`

| 字段 | 类型 | 含义 | 来源 |
|---|---|---|---|
| nodeId | str | 节点编码（全园区唯一） | A 拓扑 |
| nodeName | str | 节点名称（如"食堂"） | A 拓扑 |
| x / y | float | 地图坐标 | A 拓扑 |
| type | str | 节点类型：entrance / cross_road / divergence / hotspot / stop | A 拓扑 |
| gateId | str | 门闸编号（仅 entrance 节点） | A 拓扑 → 引用 B 门闸表 |
| signalId | str | 红绿灯编号（仅配置了信号灯的节点） | A 拓扑 → 引用 B 红绿灯表 |
| edgeIds | str[] | 该节点关联的边编号列表 | A 拓扑 |
| people | int | 实时人数 | **F 仿真引擎** |
| density | float | 实时密度（0~1） | **F 仿真引擎** |
| level | str | 实时拥挤等级：low / medium / high / critical | **F 仿真引擎** |

```json
{
  "nodeId": "zone_canteen",
  "nodeName": "食堂",
  "x": 460,
  "y": 180,
  "type": "hotspot",
  "people": 1200,
  "density": 0.8,
  "level": "high",
  "gateId": "G01",
  "signalId": "S01",
  "edgeIds": ["E05", "E14"]
}
```

### 3.2 ② 路段热度指标接口

`GET /api/v1/network/hotness`（FR-08 输出）

| 字段 | 类型 | 含义 |
|---|---|---|
| nodeId | str | 节点编码 |
| pagerank | float | PageRank 得分（0~1） |
| betweenness | float | 中介中心性 |
| heatScore | float | 综合热度分（0~100，算法归一化） |
| rank | int | 热度排行（1 = 最热） |

```json
{
  "nodeId": "zone_canteen",
  "pagerank": 0.21,
  "betweenness": 156.4,
  "heatScore": 92.5,
  "rank": 1
}
```

### 3.3 ③ 最短路径查询接口

`GET /api/v1/network/shortest-path?src=&dst=`（FR-07 输出）

| 字段 | 类型 | 含义 |
|---|---|---|
| src / dst | str（请求参数） | 起终点 nodeId |
| path | str[] | 途径节点列表（含起终点） |
| travelTime | float | 通行时间（分钟） |

```json
{
  "src": "gate_north",
  "dst": "zone_canteen",
  "path": ["gate_north", "cross_1", "diverg_1", "cross_4", "zone_canteen"],
  "travelTime": 6.2
}
```

### 3.4 ④ 热点区域分析接口

`GET /api/v1/network/hotspots`（FR-09 输出）

| 字段 | 类型 | 含义 |
|---|---|---|
| region | str | 热点区域标识 |
| nodeIds | str[] | 该区域覆盖的节点 |
| attractScore | float | AttractRank 吸引度得分 |

```json
{
  "region": "canteen_area",
  "nodeIds": ["zone_canteen", "cross_4"],
  "attractScore": 88.0
}
```

## 四、数据流向总览

```
┌─────────────────────────────────────────────────────────────┐
│                        A（姚晨 · 宏观算法）                    │
│  topology.yaml (nodes + edges)                              │
│  ▲ node_id 唯一来源                                          │
└───┬─────────────────────────┬──────────────┬────────────────┘
    │                         │              │
    ▼                         ▼              ▼
   F（张丹）                B（张紫桐）     C（陈思敏）
   仿真引擎加载              后端 REST       CAV 路径输入
   node_id/density         四个接口封装     shortest-path
    │                         │              │
    ▼                         ▼              │
   A（回传密度）             E（廖思颖）      │
   PageRank/中介中心性       前端大屏消费      │
                               ▲              │
                               │              │
                               └──────────────┘
                               A→B→C：最短路径
```

| 交付方 | 接收方 | 交付内容 | 格式 |
|---|---|---|---|
| A | F | 拓扑文件（nodes + edges） | `topology.yaml` |
| A | B | 四个接口字段定义（节点/热度/路径/热点） | REST JSON（camelCase） |
| A | C | 最短路径输出（path / travelTime） | 通过 B 的 API 中转 |
| A | E | 间接：通过 B 接口消费（地图点位/热度/热点） | — |
| F | A | 全节点时序密度（tick / node_id / density） | 用于 PageRank 验证 |
