## 一、概述

`simulation/` 是园区安全智能调控平台的**核心仿真引擎包**：支撑 3000+（验收 8000）人/车同屏模拟，
为 A（宏观拓扑）、C（微观车联网）、D（AI 密度预测）、E（前端大屏）提供统一数据与算法输入。

本实现相对设计文档 v1 的两处增量（已定稿确认）：

1. **红绿灯完整信号周期**：7 个 `has_traffic_light` 节点按周期状态机（green/yellow/red）运转，车辆/行人按遵守率放行，`SignalPolicyController` 对齐 B 冻结的《红绿灯接口.md》契约。
2. **密度口径**：与已交付生成器 `density_series.csv` 完全一致（src 等待 + dst 停留计入节点密度），可做逐节点统计校验。

### 1.1 需求映射

| 需求 | 说明 | 本包实现 |
|---|---|---|
| FR-16 | 核心仿真引擎（3000+ 同屏） | `engine.py` TickEngine |

| FR-18 | 宏观-微观联合调控 | `joint_regulator.py` |

## 三、快速上手

### 3.1 最小可运行示例（500 人 1 天，跑 1 小时模拟）

```python
# demo.py（放在 工作区/F zdzdzdzdz/ 下运行）
from simulation import Topology, FlowDataGenerator, TickEngine
from simulation import GatePolicyController, JointRegulator

# 1. 拓扑（自动加载 A 的 graph_data.yaml）
topo = Topology()

# 2. 数据生成器（FR-17，已交付）：500 人 / 50 车 / 1 天 / 可复现种子
gen = FlowDataGenerator(n_people=500, n_vehicles=50, random_state=42, n_days=1)
gen.generate()

# 3. 引擎（门闸 + 联合调控 + 红绿灯全开）
eng = TickEngine(topo, gen,
                 gate_policy=GatePolicyController(),
                 joint_regulator=JointRegulator(),
                 enable_signals=True)

# 4. 逐 tick 推进：返回冻结密度快照（对齐 8.2 接口）
snap = eng.step(0)
print(snap["tick"], snap["timestamp"], snap["nodes"][0])

# 5. 连续运行 3600 tick（1 小时）
result = eng.run(3600)
print("tick 均耗时 ms:", result.report["tick_mean_ms"])
print("在场均值:", result.report["avg_active"])

# 6. 导出密度序列 CSV（对接 E/D/B）
eng.export_snapshot_csv("data/engine_density.csv")
```

## 四、实体模型

### 4.1 实体结构化数组（`entities.py`）

人/车共用一张定长结构化表，按 `kind` 区分，避免 8000+ Python 对象的 GC 与内存开销。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int32 | 唯一 ID（递增，不复用） |
| `kind` | int8 | 0=行人，1=车辆 |
| `src_node` / `dst_node` | int32 | 起点/终点节点**序号**（非编码） |
| `state` | int8 | 状态机 0~3（见 §4.2） |
| `cur_node` | int32 | 当前所在节点（等待/停留/排队时 ≥0；移动时=当前边起点） |
| `edge_target` | int32 | 移动时当前边终点节点（在节点上时为 -1） |
| `edge_pos` | float32 | 沿当前边行进偏移（米） |
| `speed` | float32 | 当前速度（m/s） |
| `wait_ticks` | int32 | 剩余等待/停留 tick 计数 |
| `path_pos` | int32 | 路径节点序列下标（指向当前所在/刚经过的节点） |
| `active` | bool | 是否在场 |

### 4.2 四态状态机

| state | 常量 | 含义 | 触发条件 | 出口 |
|---|---|---|---|---|
| 0 | `STATE_WAIT_SRC` | 在 src 等待（出发前排队/过闸） | 实体生成时 | 等待计时归零 → 上第一条边 |
| 1 | `STATE_TRAVEL` | 沿边移动 | 等待结束 / 信号放行 | `edge_pos ≥ 边长` 到达节点 |
| 2 | `STATE_DWELL_DST` | 在 dst 停留 | 到达终点 | 停留计时归零 → 回收（active=False） |
| 3 | `STATE_WAIT_SIGNAL` | 信号路口排队 | 到达信号节点且遇红灯且遵守 | 绿灯放行 → 继续移动 |

等待时长：`state 0` 按 **src 节点类型** 采样 `WAIT_MIN~WAIT_MAX`（分钟×60=tick）；
`state 2` 按 **dst 节点类型** 采样 `DWELL_MIN~DWELL_MAX`。与生成器口径完全一致（常量复用于 `flow_data_generator.py`）。

### 4.3 EntityPool（预分配池）

| 方法/属性 | 说明 |
|---|---|
| `allocate(n) -> slots` | 分配 n 个空闲槽位，返回槽位下标数组 |
| `set_path(slot, path)` / `path(slot)` | 按槽位存取路径序号序列 |
| `recycle(mask)` / `recycle_ids(ids)` | 回收槽位（清路径 + 入空闲栈） |
| `active_mask` / `n_active` | 在场掩码 / 在场数 |
| `n_spawned` / `n_recycled` | 累计生成 / 回收数（校验"无实体丢失"用） |

> **重要**：结构化数组 **fancy 索引返回副本**。写入必须"字段优先"：
> ```python
> pool.data["kind"][slots] = kinds   # ✅ 就地写入
> d = pool.data[slots]; d["kind"] = kinds   # ❌ 写入副本，丢失
> ```
> 引擎内部已全部按此规范实现。

## 五、config.yaml 配置全解

路径均相对配置文件所在目录（`F zdzdzdzdz/`）解析；可整体覆盖，缺省值内置在 `config.py`。

```yaml
simulation:
  seed: 42                  # 随机种子（等待/停留时长等，保证可复现）
  dt: 1.0                   # 每 tick 模拟秒数（1 tick = 1 s）
  max_capacity: 10000       # 实体池预分配上限（>8000 并发量）
  tick_hz: 1                # 实时目标 1 tick/s（压测按最快速度跑，不依赖此项）
  check_interval: 10        # 联合调控触发间隔（tick）
  enable_signals: true      # 是否启用红绿灯完整信号周期
  vehicle_compliance: 1.0   # 车辆遵守信号比例（0~1）
  ped_compliance: 0.3       # 行人遵守信号比例（0~1；0=行人无视红灯）

topology:
  file: ../../项目目录/graph_data.yaml   # A 输出的拓扑（node_id 唯一来源，8.2 钉死项）
  a_module_dir: ../../项目目录           # A 的 DjShortCut.py 所在目录（sys.path 注入）

paths:
  data_dir: ./data          # 数据集/导出目录
  log_dir: ./logs           # 日志目录（预留）
```

> **sys.path 三源注入**（`config.py` 自动完成，无需手动设置）：
> 1. F 工作区目录 → `import flow_data_generator`
> 2. simulation 包目录 → 包式 `import simulation` 时绝对导入可用
> 3. A 模块目录（`topology.a_module_dir`）→ `import DjShortCut`

## 六、核心 API 详解

### 6.1 Topology（`topology.py`）

```python
topo = Topology(yaml_path=None)   # 缺省用 config.yaml 的 topology.file
```

| 属性 | 说明 |
|---|---|
| `node_ids` | 61 个节点编码列表（与 A 拓扑顺序一致，亦与生成器 NODE_LIST 对齐） |
| `n_nodes` | 61 |
| `edge_length` | (61,61) 边长矩阵（米），无直接边为 -1 |
| `capacities` | (61,) 节点容量（density = people / 容量） |
| `node_types` / `node_type_idx` | 类型列表 / 类型序号数组 |
| `is_signal` / `is_gate` / `is_entrance` | 信号灯 / 门闸 / 校门掩码 |
| `signal_nodes` / `gate_nodes` | 信号节点序列表（7 个）/ 入口门闸序列表（3 个） |
| `xy` | (61,2) 坐标（供 E 画图） |

| 方法 | 说明 |
|---|---|
| `node(node_id)` | 编码 → 序号（不存在返回 -1） |
| `node_name(idx)` | 序号 → 编码 |
| `edge_len(src, dst)` | 边长（米），无边返回 -1 |
| `path(src, dst)` | **最短路径序号序列（Dijkstra，按 (src,dst) 惰性缓存）** |
| `path_nodes(src, dst)` | 同 path，返回编码列表（调试用） |
| `n_cached_paths()` | 已缓存路径数 |
| `base_speed(kind)` | 行人 1.3 / 车辆 5.0（m/s，与生成器一致） |

> **路径缓存机制**：61 节点最多 61×60=3660 个唯一 (src,dst) 组合，实体生成时只查一次缓存，
> 运行期 tick 内是纯索引查询 —— 这是 8000 性能的关键设计之一。

### 6.2 TickEngine（`engine.py`）—— 主入口

```python
TickEngine(topology, flow_generator,
           gate_policy=None, joint_regulator=None, signal_controller=None,
           movement=None, dt=1.0, max_capacity=10000, seed=42,
           enable_signals=True, vehicle_compliance=1.0, ped_compliance=0.3,
           check_interval=10, start_hour=6)
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `topology` | 必填 | Topology 实例 |
| `flow_generator` | 必填 | 须提供 `sample(tick)`（FlowDataGenerator） |
| `gate_policy` | None | 门闸控制器；None=不限流 |
| `joint_regulator` | None | 联合调控器 |
| `signal_controller` | None | 红绿灯；enable_signals 时缺省自动构建 |
| `movement` | 常量速度 | 移动模型（C 可替换） |
| `dt` | 1.0 | 每 tick 模拟秒数 |
| `max_capacity` | 10000 | 实体池上限 |
| `seed` | 42 | 随机种子 |
| `enable_signals` | True | 红绿灯开关 |
| `vehicle_compliance` / `ped_compliance` | 1.0 / 0.3 | 遵守率 |
| `check_interval` | 10 | 联合调控触发间隔 |
| `start_hour` | 6 | 模拟起始时刻（timestamp 用） |

**方法/属性**：

| 名称 | 返回 | 说明 |
|---|---|---|
| `reset()` | self | 复位到初始状态 |
| `step(tick)` | dict | 推进 1 tick，返回冻结密度快照（字段见 §6.3） |
| `run(n_ticks)` | SimulationResult | 连续运行 n tick |
| `density` | (n_nodes,2) | 当前全节点人数/车辆数 |
| `people_density` | (n_nodes,) | 综合密度 = 人数/容量 |
| `state` | dict | 当前引擎状态（供调控器/外部读） |
| `set_heat(heat)` | None | 注入 A 的宏观热度（n_nodes,），供 JointRegulator 用 |
| `export_snapshot_csv(path)` | Path | 已运行密度序列落盘 CSV（字段见 §八） |
| `metrics` / `last_timings` | — | 指标容器 / 最近 1 tick 分模块耗时（秒） |

`SimulationResult` 字段：`n_ticks` / `report`（性能汇总）/ `density_series`（逐 tick 密度列表）/
`final_density` / `last_snapshot`。

**单 tick 内部流程**（模块计时均可在 `report["module_mean_ms"]` 查看）：

```
1. 流入 sample(tick) → 门闸限流排队 → 批量 spawn（路径缓存 + 等待时长采样）
2. movement.update_speed          # 常速模型；C 的 IDM/CAV 在此覆盖
3. 状态机：
   - state0 等待 → 到期上第一条边
   - state1 沿边 edge_pos += speed*dt → 到达节点（掩码提取子集）
        → 终点？→ state2 停留
        → 信号节点红灯且遵守？→ state3 排队
        → 否则切下一条边
   - state2 停留 → 到期回收
4. 信号放行：绿灯相位按 throughput_cap 放行 state3 排队实体
5. 密度聚合 np.bincount（state != 1 的实体按所在节点分人/车）
6. 调控：门闸每 tick 更新放行上限；联合调控每 check_interval 调用
7. metrics 记录耗时/吞吐/密度
```

### 6.3 冻结密度快照字段（对齐 8.2 协作1，B 已冻结）

`step(tick)` 返回 `{tick, timestamp, density, nodes, signals, gates, joint_plan}`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tick` | int | tick 序号（=秒） |
| `timestamp` | str | 模拟时间 HH:MM:SS（`start_hour` 起算） |
| `density` | ndarray (n_nodes,2) | 全节点 [人数, 车辆数] |
| `nodes` | list[dict] | 每节点 `{node_id, people, vehicles, density, level}` |
| `signals` | dict | 各信号节点状态（phase/throughput_cap/...，见 §6.5） |
| `gates` | dict | 各门闸策略（mode/throughput_cap/n_lanes） |
| `joint_plan` | dict | 最近一次联合调控计划（regions/global_plan） |

`level` 阈值（与生成器一致）：`density < 0.3 → low`；`< 0.6 → medium`；`< 0.9 → high`；`≥ 0.9 → critical`。

> **密度口径**：只统计"在节点上"的实体（state 0/2/3 所在节点），移动中的实体（state 1）不计数 ——
> 与 `density_series.csv` 的"src 等待 + dst 停留"占用模型一致，因此可逐节点校验。

### 6.4 GatePolicyController（`gate_policy.py`，FR-19）

```python
GatePolicyController(window_size=10, open_threshold=0.5, close_threshold=0.3,
                     max_lanes=4, min_lanes=1, base_throughput=45.0)
```

| 方法 | 说明 |
|---|---|
| `fit(history)` | EWMA + 分位数自适应学习阈值（存 `open_threshold_`/`close_threshold_`） |
| `predict(density_now, gate_id=None)` | 返回放行策略 |
| `get_params` / `set_params` | 在线调参 |

**滞回逻辑**（防开关抖动）：

| 条件 | mode | throughput_cap | n_lanes |
|---|---|---|---|
| density ≥ open_threshold × 1.8 | `close` | 0 | min_lanes |
| density ≥ open_threshold | `restrict` | base × 0.3 × min_lanes | max_lanes−1 |
| density ≤ close_threshold | `open` | base × max_lanes | max_lanes |
| 滞回带（open 与 close 之间） | 保持上次 | — | — |

引擎把该策略应用到**入口门闸节点**（gate_south/west/east）的**行人**放行：每 tick 放行数 ≤
`throughput_cap`，超限的排在 `_pending` 队列等后续 tick。车辆不受门闸限制（走红绿灯）。

### 6.5 SignalPolicyController（`signal_policy.py`，FR-19 红绿灯扩展）

```python
SignalPolicyController(signal_config=None, base_throughput=90, random_state=None)
SignalPolicyController().fit(topology, signal_config=None)
```

**默认配时表**（7 个信号节点，config 可覆盖）：

| 节点 | signal_id | green/yellow/red | cycle_time |
|---|---|---|---|
| gate_south / gate_west / gate_east | S01/S02/S03 | 15 / 2 / 13 | 30s |
| cross_zh_south / cross_zh_mid / cross_zh_north / rd_guanggong_1 | S04~S07 | 30 / 3 / 27 | 60s |

| 方法 | 说明 |
|---|---|
| `predict(tick)` | 返回 `{node_idx: {...}}` 全信号状态（含 phase/signal_flow_rate） |
| `passable(node_idx, tick)` | 该节点此刻是否可放行（green/off） |
| `adjust(node_idx, density)` | mode='adaptive' 时按路口密度调 green_time（FR-19 自适应钩子） |
| `get_params` / `set_params` | 在线调参 |

**相位计算**：`t = (tick + offset) % cycle_time`；`t < green_time → green`；
`t < green_time + yellow_time → yellow`；否则 `red`。`signal_status`：0 熄灭→自由通行(off)，
2 黄闪→按可放行(off)，3 故障→按红灯(red)，1 正常→按相位。

`predict` 字段对齐 B 冻结契约：`signal_id, node_id, phase, mode, cycle_time, green_time,
yellow_time, red_time, offset, throughput_cap, n_phases, signal_status, signal_flow_rate`。

**引擎联动**：
- 实体到达信号节点时查 `passable`，红灯且遵守（车辆 100%，行人按 `ped_compliance`）→ state 3 排队；
- 绿灯相位按 `throughput_cap`（单位 tick）放行排队实体（先到先走）；
- 排队实体计入该路口密度 → `cross_zh_*` 路口不再恒为 0。

### 6.6 JointRegulator（`joint_regulator.py`，FR-18）

```python
JointRegulator(check_interval=10, budget_pool=100.0, decay=0.5,
               dense_threshold=0.6, top_k=5)
```

| 方法 | 说明 |
|---|---|
| `fit(macro_cfg)` | 学习拓扑节点集合（macro_cfg 含 `node_ids`） |
| `predict(state)` | 返回 `{regions:[{region_id, priority, compute_budget}], global_plan}` |
| `get_params` / `set_params` | 在线调参 |

**简化闭环**（8.6 与 A/C 联调可在此扩展）：
1. 每 `check_interval` tick，读取 `state`（含 density、可选 heat）；
2. 打分 `score = density + 0.5 × heat`，识别 `density ≥ dense_threshold` 的密集区并排序；
3. 从 `budget_pool` 按优先级分配预算，闲置区按 `decay` 回收；
4. 输出 `global_plan`：`focus_dense`（存在超阈密集区）或 `normal`。

## 七、压力测试（NFR-01 / FR-20）

### 7.1 三个入口的区别

| 入口 | 用途 | 说明 |
|---|---|---|
| `run_level(n_entities, n_ticks=100, warmup=10)` | **纯并发成本** | 预灌 n 个在场实体（随机边中段，state=1），测每 tick 全量状态机/移动/聚合耗时；压测主指标 |
| `run_integration(n_people, n_vehicles, n_ticks=3600, warmup=10)` | 全链路集成 | 生成器流入 + 门闸 + 信号 + 调控，8.6/8.7 正式使用 |
| `verify_baseline(n_people=200, n_vehicles=20, n_ticks=2000)` | 正确性 | 结构不变量（硬）+ 与生成器密度统计对齐（软） |

> 为什么 `run_level` 预灌而不是靠生成器流入？生成器把 8000 人摊在 16 小时（57600 tick）内到达，
> 前 100 tick 实际在场极少，测不出 8000 并发成本。预灌直接压满并发群体，测量每 tick 全量成本。

### 7.2 判定标准（设计文档 §8.3）

| 指标 | 4000 预压门槛 | 8000 正式门槛 | 实测(8000) |
|---|---|---|---|
| tick 平均时延 | < 100 ms | < 100 ms | **3.26 ms** |
| tick p95 时延 | < 300 ms | < 300 ms | **4.67 ms** |
| 内存峰值 | < 2 GB | < 3 GB | **5.8 MB** |
| 实体吞吐 | ≥ 20000 实体/s | ≥ 40000 实体/s | **245 万 实体/s** |

> 吞吐口径：`平均在场实体 / tick 均耗时`（每秒可推进的实体数）。

### 7.4 正确性校验（verify_baseline）

硬断言（不满足即 False）：
- **无实体丢失**：`spawned == active + recycled`；
- 密度非负且不超安全上界（≤10.0，density 允许 >1）。

软断言：`enable_signals=False` 口径下，引擎每节点人数与生成器 `density_series`
在公共采样 tick 的 Pearson 相关 ≥ 0.5。实测 **0.857**（出行时间因走真实网络路径略长于生成器的直线距离，
属统计一致而非逐点相等）。

> 若想逐点对齐，可在 baseline 模式下跑短程场景（生成器按直线速度、引擎按网络边长，
> 长程差异小、短程差异大），或后续让生成器复用同一路径表（扩展项）。

## 九、扩展点与健壮性

### 9.1 插件化替换点（设计文档 §7.1）

| 替换点 | 基类/接口 | 可替换实现 |
|---|---|---|
| 微观移动 | `movement.BaseMovement` | 匀速（默认）/ IDM / CAV 跟驰（C） |
| 路径规划 | A 的 `ShortestPathFinder` | Dijkstra / 密度加权 / 局部绕行 |
| 门闸策略 | `GatePolicyController` | 阈值 / 学习型 / 强化学习 |
| 红绿灯策略 | `SignalPolicyController` | 固定周期 / adaptive（已预留 adjust 钩子） |
| 数据生成 | `FlowDataGenerator` | 泊松 / 真实数据回放 |

接入方式：实现同一接口后在 `config.yaml` 指定类名即可，引擎代码零改动。

### 9.2 健壮性（要求七）

- 节点编码一致性校验：`TickEngine.__init__` 校验 `flow_generator.node_ids == topology.node_ids`，
  不一致直接抛错（8.2"node_id 以 A 拓扑为唯一来源"钉死项）；
- 实体池满时按实际可分配量截断，不越界；
- 信号/门闸/调控器接口均为 sklearn 风格 `fit/predict/get_params/set_params`，便于在线调参与单测。

### 9.3 常见问题（FAQ）

| 现象 | 原因 / 解决 |
|---|---|
| `ModuleNotFoundError: DjShortCut` | 检查 `config.yaml` 的 `topology.a_module_dir` 指向 `项目目录`；需先 `get_config()` 触发注入 |
| 实体人数不涨 / density 全 0 | 前 1 千多 tick 内生成器无出生实体（birth_tick 从 ~1300 起）；把 `n_ticks` 调大或改用 `run_level` 预灌 |
| `no_loss: False` | 实体被分配但未写入（结构化数组副本陷阱）→ 引擎内部已修复，勿用 `d = data[slots]; d[...] = ...` 写法 |
| 路口 density 与生成器不符 | 开启信号后 `cross_zh_*` 有排队密度，属正常；校验请用 `enable_signals=False` 的 baseline 口径 |
| A 换了拓扑编码 | 重新生成 `data/` 数据集（`python flow_data_generator.py`），并保证 `graph_data.yaml` 与生成器 NODE_LIST 顺序一致 |
