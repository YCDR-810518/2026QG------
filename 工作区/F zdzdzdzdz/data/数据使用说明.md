## 二、文件字段说明

### 2.1 people.csv（行人出行计划）

| 字段       | 类型 | 含义                                                                                                                                              |
| ---------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| id         | int  | 实体唯一 ID（跨天连续编号）                                                                                                                       |
| birth_tick | int  | 出生 tick（1 tick = 1 秒）。**距起始日 06:00 的模拟秒，跨天连续**：每天只模拟 6:00–22:00（16h），day1 06:00 = tick 57600，day2 = 115200 … |
| src_node   | str  | 起点节点编码（与拓扑一致）                                                                                                                        |
| dst_node   | str  | 终点节点编码（热点区域等）                                                                                                                        |
| kind       | int  | 恒为 0（行人）                                                                                                                                    |

> 语义：一个人从 `src_node` 在 `birth_tick` 时刻出发，前往 `dst_node`。

### 2.2 vehicles.csv（车辆流入计划）

| 字段                                  | 类型      | 含义                                   |
| ------------------------------------- | --------- | -------------------------------------- |
| id / birth_tick / src_node / dst_node | 同 people | —                                     |
| kind                                  | int       | 恒为 1（车辆）                         |
| is_internal                           | int       | 0=外来车，1=园区内部车（默认比例 0.4） |

### 2.3 density_series.csv（密度时序，D 训练主数据）

| 字段           | 类型  | 含义                                                                    |
| -------------- | ----- | ----------------------------------------------------------------------- |
| tick           | int   | 模拟秒（0 ~ 403140）                                                    |
| timestamp      | str   | **完整日期时间 `YYYY-MM-DD HH:MM:SS`**（06:00 起，每 60s 一行） |
| node_id        | str   | 节点编码                                                                |
| people         | int   | 该节点当前人数（含"出发前在 src 等待" + "在 dst 停留"）                 |
| vehicles       | int   | 该节点当前车辆数                                                        |
| density        | float | 综合密度 = people / 节点容量（0~1+）                                    |
| level          | str   | low / medium / high / critical                                          |
| gate_status    | int   | 门闸状态（0=关闭, 1=正常开放, 2=限流）                                  |
| gate_flow_rate | float | 门闸通行速率（人/分钟）                                                 |

> - `level` 阈值：density < 0.3 low，< 0.6 medium，< 0.9 high，≥ 0.9 critical
> - `gate` 字段在入口节点（gate_*）语义完整；非入口节点按同一密度规则派生，仅供训练辅助特征，门闸异常检测请以入口节点为准
> - 4000 人/天规模下门闸瞬时占用很低（人流快速通过），`gate_status` 多为开放状态属正常；正式 8000 压测数据会接近限流

## 三、按星期几调整人流（v2.0 核心）

每天使用一条独立的 24h 相对到达强度曲线（`day_profiles`：mon~sun）。默认：工作日×5 + sat + sun，体现"周一返校、周五离校、周末休闲"的差异。

| 节点类型        | 工作日 mon~fri                               | 周六 sat                                     | 周日 sun               |
| --------------- | -------------------------------------------- | -------------------------------------------- | ---------------------- |
| 门闸 entrance   | 早7-9(8)、晚17-19(6)；**周一早更强**   | 9-11(5)、晚17-19(6)                          | 10-12(4)、晚17-19(6)   |
| 食堂 canteen    | 早7-9(3)、午11-13(9)、晚17-19(9)             | 午11-13(8)、晚17-19(8)，**无早餐高峰** | 午11-13(7)、晚17-19(8) |
| 宿舍 dorm       | 早6-8(7)、晚21-23(4)；**周五夜更强**   | 9-11(3)、21-23(4)                            | 9-11(3)、21-23(3)      |
| 教学楼 academic | 8-12(5)、14-17(5)；**周一早更强**      | 9-12(3)、14-17(3)                            | 仅14-17(2)             |
| 实验楼 lab      | 9-12(5)、14-17(5)                            | 9-12(2)、14-17(2)                            | 平静                   |
| 运动场馆 sports | 晚18-21(8)、午12-14(2)；**周五晚更强** | 午14-17(5)、晚18-21(8)                       | 午14-17(6)、晚18-21(7) |
| 行政 admin      | 9-11(5)、14-16(4)                            | 9-11(2)                                      | 9-11(2)                |

括号内为相对强度（基数 1.0 表示该小时到达强度 = 峰值占比 × 总人数）。

已验证现象：周六食堂 7-9 点人数为 0（无早餐高峰），工作日同段有人流；周五晚/夜间宿舍人数高于周三。

## 四、数据是怎么生成的（一句话模型）

```
按星期几的节点时变强度曲线(node_curves) → 泊松到达(λ_i(t) = N × curve_i(t)/Σcurve)
  → 目的地按时变吸引度抽样(OD×容量×curve_dst(t)) → src等待 + dst停留(dwell) → 离开
```

关键点：

- **概率控制生成点**：每 tick 某节点成为"生成点"的概率 = `curve_i(t) / Σ curve_k(t)`
- **时变目的地**：食堂在午/晚高峰吸引度自动升高 → 人流大；节假日曲线切换后自动跟随
- **density_level 峰化指数**：off_peak=0.8 / peak=2.0 / ultra_peak=3.0，ultra_peak 产生 critical 样本
- 重新生成：`python ../flow_data_generator.py`（`random_state=42` 可复现）

## 五、给 D（李世涵）的模型衔接示例

D 的 `d_mindspore/model.py` 已实现 `DensityPredictor`（TSMixer/GRU）与 `CongestionDetector`，需要把长表 CSV 转成模型要求的张量。下面是对齐他默认参数的最小衔接代码。

### 5.1 数据准备：长表 → 宽表

```python
import numpy as np, pandas as pd
from model import DensityPredictor, CongestionDetector

df = pd.read_csv("data/density_series.csv", dtype={"node_id": str})
df["ts"] = pd.to_datetime(df["timestamp"])
df["hour"] = df["ts"].dt.hour
df["dow"] = df["ts"].dt.dayofweek          # 0=周一 … 6=周日

nodes = sorted(df["node_id"].unique())
n_nodes, F = len(nodes), 6

def wide(col):
    t = df.pivot_table(index="ts", columns="node_id", values=col).reindex(columns=nodes)
    return t.fillna(method="ffill").fillna(0.0)

# 特征列顺序固定，与 CongestionDetector 默认 *_feature_idx 对齐：
#   density=0, vehicles=1, gate_status=2, gate_flow_rate=3, hour_sin=4, hour_cos=5
T_all = df["ts"].drop_duplicates()
feat = np.stack([
    wide("density").values,
    wide("vehicles").values,
    wide("gate_status").values,
    wide("gate_flow_rate").values,
    np.sin(T_all.dt.hour * 2 * np.pi / 24)[:, None] * np.ones(n_nodes),
    np.cos(T_all.dt.hour * 2 * np.pi / 24)[:, None] * np.ones(n_nodes),
], axis=-1)                       # (n_timesteps, n_nodes, F)
```

### 5.2 DensityPredictor：滑窗造样本

```python
W, H = 60, 10                     # 历史窗口 / 预测步长
density = wide("density").values  # (T, N)
X, y = [], []
for t in range(W, len(feat) - H):
    X.append(feat[t - W:t])       # (W, N, F)
    y.append(density[t:t + H])    # (H, N)
X = np.transpose(np.stack(X), (0, 2, 1, 3))  # (n_samples, n_nodes, W, F)
y = np.transpose(np.stack(y), (0, 2, 1))    # (n_samples, n_nodes, H)

dp = DensityPredictor(window_size=W, pred_horizon=H, model_type="tsmixer")
dp.fit(X, y, epochs=100, batch_size=32, val_split=0.15, feature_names=["density","vehicles","gate_status","gate_flow","hour_sin","hour_cos"])
dp.save("checkpoints/density_predictor")
```

### 5.3 CongestionDetector：历史基线 + 实时检测

```python
cd = CongestionDetector(density_percentile=95.0,
                        density_feature_idx=0, gate_status_feature_idx=2, gate_flow_feature_idx=3)
X_hist = feat[: len(feat) * 3 // 4]   # 用前 75% 作为"正常"基线
cd.fit(X_hist)

X_now = feat[-10:]                    # 最近 10 帧（可检测滞留）
events = cd.predict(X_now, X_pred=None)
# events: [{"type":"congestion"/"loitering"/"gate_anomaly", "severity":"L2"/"L3", ...}]
```

> 时间切分务必按时间顺序（训练取前段、测试取后段），避免未来信息泄露（详见《AI模型设计文档.md》§2.3）。

## 六、各消费方怎么用

### 6.1 给 C（陈思敏 · 微观/CAV 准入）

- `vehicles.csv` 的车辆实体字段（id / srcNode / dstNode / birthTick / isInternal）作为车辆进出计划输入
- `density_series.csv` 的 densityStats（people / vehicles / density）作为准入算法判断"园区挤不挤"

### 6.2 给 E（廖思颖 · 前端大屏）

- `node_id` + A 拓扑坐标 → 点位
- `density` → 热力图颜色浓度
- 按 `timestamp` 的时序（含日期）→ 密度曲线，可切换"某天/星期几"视图

### 6.3 给 TickEngine（F 引擎，FR-16）

- 引擎逐 tick 从生成器取流入：`gen.sample(tick)`（`birth_tick` 跨天连续，day0 与单天数据完全一致 → 现有引擎配置零改动）
- 多天运行只需把引擎 `n_ticks` 调为 `n_days×57600`
- `density_series.csv` 可作为引擎输出的校验基准（人工抽样对比）

## 七、注意事项

- **规模**：首版交付 7 天（4000 人/天）；正式压测 8000 时用 `n_people=8000, n_days=1` 重生成即可
- **可复现**：`random_state=42` 固定，同一参数重复生成结果一致
- **节点编码**：当前取自 `可视化的图.py`；A 交付正式 `topology.json` 后需切换编码并重新生成
- **不适用场景**：本数据为"到达 → 热点停留 → 离开"的占用模型，未包含道路中间段（交叉口/边）的通行细节，微观路径仿真请以 TickEngine 输出为准
