# 门闸管理说明

> 园区大门闸（gate_*）车辆入园调控算法说明。
> 涉及模块：`simulation/controller.py`（决策）、`simulation/engine.py`（执行）、`simulation/main.py`（组装）。
> 关联需求：FR-19（门闸调控）。

---

## 一、采用什么

门闸管理采用**密度滞回控制算法**，由以下三层构成：

| 层 | 模块 | 职责 |
|---|---|---|
| 决策层 | `simulation/controller.py::HysteresisPolicyController(role="gate")` | 根据大门车辆密度输出闸机模式与放行上限 |
| 执行层 | `simulation/engine.py::_regulate` + `_ingest` | 每 tick 更新 `_gate_caps[g]`，对入园车辆按上限排队限流 |
| 组装层 | `simulation/main.py::_build_engine` | 构造 `gate_policy=HysteresisPolicyController(role="gate")` 注入引擎 |

实际生效门闸：3 个（`gate_south` / `gate_west` / `gate_east`，由 `Topology.gate_nodes` = `is_gate & is_entrance` 决定）。

补充：
- 大门闸**只控制车辆入园**，不控制行人（行人无论 src 是否为大门口都直接生成）。
- 红绿灯（`SignalPolicyController`）控制路口通行，与门闸相互独立、不重复限流。
- 联合调控器 `JointRegulator`（FR-18）为预留位，当前不回写门闸吞吐。

---

## 二、怎么运作

### 1. 感知
每 tick，引擎 `_aggregate` 统计各节点在场车辆数，得到大门节点车辆密度：

```
d[g] = vehicle_density[g]   # 大门 g 的车辆数 / 该节点容量
```

### 2. 决策（滞回状态机）
`HysteresisPolicyController.predict(density_now, gate_id)` 对每个大门独立判定模式：

```
d ≥ open_threshold × max_close_ratio  →  closed   （完全关闭）
d ≥ open_threshold                    →  restricted（限流）
d ≤ close_threshold                   →  open      （正常放行）
else                                  →  保持上次模式（滞回带内不切换）
```

- 每个闸机用 `_last_modes[node_id]` **独立记忆**上次模式，避免多节点互相干扰。
- 滞回带（`close_threshold < d < open_threshold`）保持原状态，防止密度在阈值临界处反复开关门（抖动）。
- 可选 `fit(history)`：按最近 `window_size` 个历史密度做 EWMA + 分位数自适应学习阈值（open=90 分位、close=30 分位），不调用时用默认阈值。

### 3. 放行上限（throughput_cap）
不同模式给出每 tick 放行车辆数上限：

| 模式 | throughput_cap | 开闸数 n_lanes |
|---|---|---|
| open | `base_throughput × max_lanes` = 45×4 = **180** 辆/tick | 4 |
| restricted | `base_throughput × 0.3 × min_lanes` = 45×0.3×1 = **13** 辆/tick | 1 |
| closed | **0** 辆/tick | min_lanes |

### 4. 执行（引擎排队限流）
- `_regulate`（每 tick）：对每个大门 `g`，`_gate_caps[g] = pol["throughput_cap"]`，并缓存 `_gate_policies[g]`。
- `_ingest`：src 为大门的车辆先进入 `_pending[g]` 队列；每 tick 只放行前 `cap` 辆（`q[:cap]`），其余顺延到下 tick 继续排队。
- 初始 `_gate_caps[g] = 10^9`（未调控前等价于不限流）。

### 5. 输出
- `engine_snapshot`：每节点行含 `gate_status`（open/restricted/closed）、`gate_flow_rate`（= throughput_cap）。
- 末 tick 快照 / union_pack：`gates = {gate_id: {mode, throughput_cap, n_lanes}}`。
- 离线数据侧：`flow_data_generator._hysteresis_series` 用相同阈值生成合成闸机状态，仅用于 data 分析产物，不影响实时仿真。

---

## 三、达到什么效果

1. **高峰限流削峰**：园内车辆密度升高时闸机自动降放行上限（restricted/closed），把入园车流挡在园外排队，避免园内道路/节点过饱和。
2. **拥堵预防**：拥堵未扩散前即收闸，保护园内路网与关键节点（大门阈值基于车辆密度，拥堵前兆即触发）。
3. **稳定不抖动**：滞回带 + 每闸独立记忆，消除阈值临界处的反复开关；`fit()` 可自适应园区作息曲线。
4. **可观测、可联调**：gate 状态与放行速率实时进入 `engine_snapshot` / union_pack，供后端与 A 宏观算法对照验证。

## 四、参数表

| 参数 | 默认值 | 含义 |
|---|---|---|
| `role` | `"gate"` | 控制器角色（gate=大门闸 / door=园内门） |
| `window_size` | 10 | 自适应阈值学习窗口（tick） |
| `open_threshold` | 0.5 | 密度达到该值进入限流（restricted） |
| `close_threshold` | 0.3 | 密度低于该值恢复正常放行（open） |
| `max_close_ratio` | 1.8 | closed 触发密度 = open_threshold 的倍数 |
| `max_lanes` | 4 | 完全放行时的开闸数（open 态） |
| `min_lanes` | 1 | 限流时的最小开闸数 |
| `base_throughput` | 45.0 | 单闸道每 tick 放行上限（辆） |

### 调参建议
- 园内道路更紧张：调低 `open_threshold`（更早限流）或调低 `base_throughput`（峰值更低）。
- 高峰更集中：缩小 `window_size` 让 `fit()` 阈值更贴近近期密度。
- 防止限流过于激进：调大 `close_threshold` 更快恢复开门，或调大 `min_lanes` 保证限流时仍有通行能力。
