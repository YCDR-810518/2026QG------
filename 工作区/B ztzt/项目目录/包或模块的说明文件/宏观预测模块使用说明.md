# 宏观预测模块使用说明（macro_predict.py）v1.0

> 模块：macro_predict.py ｜ 负责：成员 A（姚晨）
>
> 对应需求：FR-08（PageRank/中介中心性）、FR-09（AttractRank 热点区域分析）、FR-27（热力图/密度预测大屏数据）
>
> 对外接口：`DensityBatchProvider.read_batch()` + `MacroPredictor.predict_network() / predict_hotspots()`
>
> 数据来源：F 仿真引擎累计落盘的 `engine_timeseries.csv`（每 10s 追加一批，61 节点）

## 一、模块定位

读取 F 落盘的实时密度 CSV 中**最新一批**（相同 timestamp 的 61 个节点状态），
以实时密度修正边权（可叠加门/红绿灯状态），重新计算两类宏观指标，通过
**两个独立 predict 端口**分别返回 pandas DataFrame：

| 端口 | 结果 | 对应冻结接口 |
|---|---|---|
| `predict_network()` | 节点级热度（pagerank / betweenness / heatScore / rank） | `GET /api/v1/network/hotness` |
| `predict_hotspots()` | 区域级热点（region / nodeIds / attractScore） | `GET /api/v1/network/hotspots` |

```
F CsvRecorder（每 10s 追加 61 行）
        │
        ▼
DensityBatchProvider.read_batch()   ← tail 读取最新批，不整读历史
        │  density / door_status / signal_status
        ▼
MacroPredictor.predict_network() ──► TrafficNetworkAnalyzer ──► DataFrame(61×5)
MacroPredictor.predict_hotspots() ─► AttractRankAnalyzer  ──► DataFrame(N×3)
```

## 三、数据源：engine_timeseries.csv（口径已实测）

- 每 10s 追加一批，每批 = 61 行（每节点一行），**批内 timestamp 相同**，tick 每 10 一跳
- 表头 13 列（与 `engine.SNAPSHOT_CSV_FIELDS` 一致）：

```
tick,timestamp,node_id,people,vehicles,density,level,
gate_status,gate_flow_rate,door_status,door_flow_rate,signal_status,signal_flow_rate
```

- `density` = people / 节点容量（可 >1）；`door_status` ∈ {open/restricted/closed}；
  `signal_status` ∈ {green/yellow/red/off}；无该项时为空串 `""`

## 四、DensityBatchProvider —— CSV 最新批次读取器

### 4.1 构造

```python
from macro_predict import DensityBatchProvider

provider = DensityBatchProvider()                       # csv_path 缺省读 config.yaml paths.csv_file
provider = DensityBatchProvider(csv_path="./data/engine_timeseries.csv")  # 显式覆盖
```

CSV 不存在时构造抛 `FileNotFoundError`。

### 4.2 read_batch(timestamp=None, csv_path=None) → DataFrame

| 参数 | 说明 |
|---|---|
| `timestamp` | `"YYYY-MM-DD HH:MM:SS"`。None → 最新一批；指定 → 该批次（测试/回放） |
| `csv_path` | 非 None 覆盖本次路径（优先级：参数 > 构造 > config） |

**返回**：61 行 × 13 列，列名 = 表头；dtype 规范化（保证 JSON 序列化安全）：

| 列 | dtype |
|---|---|
| tick / people / vehicles | int64 |
| density | float64 |
| timestamp / node_id / level / gate_status / gate_flow_rate / door_status / door_flow_rate / signal_status / signal_flow_rate | str（空值保持 `""`） |

**读取策略**（tail，不整读）：二进制回读末尾 128 KB（≈18 批，远大于单批 7 KB）→
丢弃无换行结尾的半行（防写入中断）→ 解析并剔除表头/空行 → 不足时翻倍 512 KB 重试 →
取末行 timestamp 的全部行。历史再长（7 天 ≈ 2460 万行）也不影响单次调用开销。

**异常约定**：

| 情形 | 行为 |
|---|---|
| CSV 不存在 | `FileNotFoundError` |
| 文件仅表头 / 无匹配 timestamp | 空 DataFrame（保留 13 列表头） |

## 五、MacroPredictor —— 整合入口（两个独立端口）

### 5.1 构造

```python
from macro_predict import MacroPredictor

pred = MacroPredictor()                       # 全默认
pred = MacroPredictor(csv_path="...",        # 覆盖 CSV 路径
                      topology=None,         # Topology 实例；None 则惰性构建（读 config）
                      congestion_factor=1.0, # 拥堵修正系数 k
                      alpha=0.5)             # heatScore 中 PageRank 权重
```

### 5.2 predict_network(timestamp=None, csv_path=None) → DataFrame（端口一）

**返回**：61 行 × 5 列：

| 列 | dtype | 说明 |
|---|---|---|
| node_id | str | 节点编码 |
| pagerank | float64 | PageRank（归一化 0~1） |
| betweenness | float64 | 中介中心性 |
| heatScore | float64 | 综合热度分 0~100 |
| rank | int64 | 热度排行（1 = 最热） |

### 5.3 predict_hotspots(timestamp=None, csv_path=None) → DataFrame（端口二）

**返回**：N 行 × 3 列（N = 区域数）：

| 列 | dtype | 说明 |
|---|---|---|
| region | str | 区域标识（如 `living_1`） |
| nodeIds | list[str] | 该区域覆盖的节点 |
| attractScore | float64 | 吸引度得分 0~100 |

两个端口**各自独立**完成：读最新批 → 组装密度/门/信号 → 修正边权 → 调对应分析器 → 转 DataFrame。
无数据时均返回空 DataFrame（保留列）。列名直接对齐冻结接口字段（camelCase），B 后端可原样序列化。

## 六、密度参与边权修正（核心机制）

读取批次后：

1. `density`：整列 → `{node_id: density}`；
2. `door_status` / `signal_status`：空串跳过 → `door_states` / `signal_states`；
3. 边权在**门/信号惩罚之后**叠加拥堵修正：

```
w' = w × (1 + k × d̄)
d̄ = (density[src] + density[dst]) / 2     # 边两端节点密度均值，缺失节点按 0
k  = congestion_factor（默认 1.0，构造参数可调）
```

**数学性质**：PageRank / 中介中心性对边权的**等比缩放不变**——所有节点密度相同
（均匀密度）时热度排行不变；只有密度**分布不均匀**时，拥堵区域的邻近路段权值上调，
热度排行才会变化（自测已验证：全 0.0 vs 半 1.0 密度，heatScore Top3 发生变化）。

## 八、接入方法（供 F 选用，接入点由 F 决定）

```python
from macro_predict import MacroPredictor
pred = MacroPredictor()                      # 缺省按 config paths.csv_file 找 CSV

# 方式 A：挂 CSV 追加回调（csv 命令 / run 命令均可）
def _on_append(path, tick, rows):
    df_net = pred.predict_network()          # 61×5 节点热度
    df_hot = pred.predict_hotspots()         # N×3 热点区域
    # ... 后续打包 / 发送逻辑

run_and_record(eng, n_ticks, recorder=CsvRecorder(), interval=10,
               on_append=_on_append, ...)

# 方式 B：挂 JSON 打包回调（run 命令现有 on_package 位置）
def _on_package(files):
    df_net = pred.predict_network()
    df_hot = pred.predict_hotspots()
    # ...
    return False
```

> 时序说明：CSV 追加先于回调执行（csv_recorder.py 先 append 后回调），
> 回调内调用 `predict()` 必然取到本批数据；建议 F 在 run 开始前 truncate
> 重建表头，避免跨运行 tick 重复。
