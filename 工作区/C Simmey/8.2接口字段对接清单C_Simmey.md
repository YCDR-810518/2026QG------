## 〇、C 明天角色一句话

C 是**微观执行者与隐私守门人**：负责定义外来车辆的“准入请求与决策下发”字段，输出经过差分隐私（DP）加噪处理的车辆轨迹字段；同时与A钉死宏观路径的接收格式，与D对齐预测密度的接收方式。

## 一、给 B（张紫桐 · 后端/数据库）——核心交付

向后端交付两个核心业务接口的数据结构，以便B进行建表和API开发。

### 1.1 车辆准入决策接口 `POST /api/v1/vehicle/access`（FR-13 输出）

业务逻辑：车辆到达园区入口时发出请求，C的 `VehicleAccessPolicy` 结合实时/预测人流进行计算，返回是否准入及微观规划路径。

**① Request (请求体 - 车辆发给系统)**

| 字段（camelCase） | 类型 | 含义 | 来源约束 |
| --- | --- | --- | --- |
| vehicleId | str | 车辆唯一标识（车牌或虚拟ID） | - |
| type | str | 车辆类型（visitor/staff/emergency） | 决定准入优先级 |
| entryNode | str | 申请驶入的入口节点 | **必须是A拓扑中的entrance**<br> |
| targetNode | str | 目标节点（如"zone_canteen"） | **必须是A拓扑中的节点**<br> |

**② Response (响应体 - 系统下发给车辆)**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| isAllowed | bool | 是否允许驶入 |
| reason | str | 拒绝原因（如"区域重度拥堵"），允许则为空 |
| cavMode | bool | 是否开启车联网协同（CAV实验组用）
| plannedPath | str[] | 规划的节点ID数组（调用A的最短路径生成）

**JSON 样例（B 冻结用）：**

```json
// 请求样例
{
  "vehicleId": "粤B·12345",
  "type": "visitor",
  "entryNode": "gate_north",
  "targetNode": "zone_canteen"
}

// 响应样例
{
  "isAllowed": true,
  "reason": "",
  "cavMode": true,
  "plannedPath": ["gate_north", "cross_1", "diverg_1", "zone_canteen"]
}

```

### 1.2 差分隐私轨迹上传接口 `POST /api/v1/vehicle/trajectory`（FR-14 输出）

业务逻辑：车辆在园区内行驶的数据，必须经过 C 的 `DpNoiseScaler` 加噪处理后，才能存入B的数据库，供E展示或D分析。

**Request (请求体 - 批量上传加噪轨迹)**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| vehicleId | str | 脱敏后的车辆ID（如使用哈希值） |
| timestamp | int | 时间戳 |
| dpX | float | 加噪后的 X 坐标（Laplace 噪声）
| dpY | float | 加噪后的 Y 坐标（Laplace 噪声）

**JSON 样例（B 冻结用）：**

```json
{
  "vehicleId": "hash_8f9a2b",
  "timestamp": 1691452800,
  "dpX": 201.45, 
  "dpY": 102.12
}

```

(注：真实坐标可能在 (200, 100)，加噪后出现偏移以保护隐私)

## 二、与 A（姚晨 · 宏观算法）——双向对齐（协作4 伏笔）

| 方向 | 字段/内容 | 含义 |
| --- | --- | --- |
| A→C | 最短路径 API (`path` 数组)| C 接收该数组，作为微观车辆行驶的**宏观导航路线**。 |
| A→C | 拓扑 `node_id` 枚举值| C 的多智能体仿真网格，必须严格将路口映射到 A 定义的 `cross_1` 等 ID 上。 |
| C→A | `actualTravelTime` | 车辆走完某条边的实际耗时（含CAV协同排队时间），供A动态调整边的 `weight`。

## 三、与 D（李世涵 · AI 密度预测）及 F（张丹 · 仿真引擎）——横向拉通

### 3.1 找 D（李世涵 · AI 密度预测）要字段（协作7 伏笔）

你的 `VehicleAccessPolicy` 不能只看当前人流，必须看预测人流。

* **你需要 D 确认**：D 的预测模型 `DensityPredictor` 提供什么格式的输出？
* **你的诉求**：要求 D 提供一个类似于 `{ "nodeId": "zone_canteen", "futureDensity10min": 0.85 }` 的字段结构。如果预测10分钟后食堂密度 > 0.9，你的算法就会直接拒绝去食堂的访客车辆。

### 3.2 找 F（张丹 · 仿真引擎）要字段

F 负责生成 3000~8000 人/车的世界。

* **你需要 F 确认**：微观车辆对象的初始化状态。
* **你的诉求**：明确 F 传给你的单个车辆对象是否包含 `current_speed`, `acceleration`, `heading`（朝向）等车辆动力学字段。你的 IDM跟驰模型和 CAV 协同模型 强依赖这些字段来计算加速度。
