#### 1. 车辆准入请求字段 (Request Body)

**说明**：前端或硬件设备向后端发起准入请求时携带的数据，也是传给 `VehicleAccessPolicy` 算法作为 `vehicle_request` 样本的特征输入。

```json
{
  "vehicleId": "粤B12345",
  "vehicleType": "guest",
  "requestTime": 1722571200000,
  "entryGateId": "gate_north_01",
  "targetNodeId": "zone_canteen"
}

```

**字段详细说明：**

| 字段名 | 数据类型 | 必填 | 说明及用途 |
| --- | --- | --- | --- |
| `vehicleId` | String | 是 | 车辆唯一标识（如车牌号），用于日志追踪。
| `vehicleType` | String | 是 | 车辆类型（如 `guest` 外来车, `staff` 员工车, `emergency` 应急车），算法决策权重依据。 
| `requestTime` | Long | 是 | 请求的时间戳（毫秒），用于结合 D 成员的未来密度预测做时序对齐。
| `entryGateId` | String | 是 | 申请进入的门闸 ID，作为路径规划的起点 (`src`)。
| `targetNodeId` | String | 是 | 车辆在园区内的目的地区域/节点 ID，作为路径规划的终点 (`dst`)。         


#### 2. 车辆准入决策结果字段 (Response Body)

**说明**：后端调用算法后，返回给前端/硬件设备的决策结果。对应 `VehicleAccessPolicy.predict()` 和 `predict_proba()` 的返回产物。

```json
{
  "vehicleId": "粤B12345",
  "accessStatus": "ALLOWED",
  "accessProbability": 0.92,
  "assignedRoute": ["gate_north_01", "node_15", "node_22", "zone_canteen"],
  "rejectReason": ""
}

```

**字段详细说明 (给 B 成员构建返回体用)：**

| 字段名 | 数据类型 | 必填 | 说明及用途 |
| --- | --- | --- | --- |
| `vehicleId` | String | 是 | 对应请求的车辆标识，方便前端回调确认。 |
| `accessStatus` | String | 是 | 核心决策结果状态码：`ALLOWED` (准入), `DENIED` (拒入), `RESTRICTED` (限制路线)。对应 `predict()` 的输出。
| `accessProbability` | Float | 是 | 准入概率值（0.0 ~ 1.0），对应 `predict_proba()` 的输出。可用于大屏展示或边缘情况的柔性调控。
| `assignedRoute` | Array | 否 | 分配的行进路线节点 ID 列表。仅在状态为 `ALLOWED` 或 `RESTRICTED` 时返回，结合 A 成员的宏观最短路径生成。在开启隐私保护时，此路径需经过 `DpNoiseScaler` 加噪处理。
| `rejectReason` | String | 否 | 拒绝准入的原因说明（如“目标区域人流过载”、“系统拥堵预警中”），仅在 `DENIED` 时返回。 |
